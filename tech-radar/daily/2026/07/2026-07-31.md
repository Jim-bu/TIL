## 🔵 Tech → Product (기술에서 서비스로)

**different-ai/openwork(오픈 워크스페이스) → 에이전트 워크스페이스 카테고리(Claude Cowork·Campus·Nautis)**

`openwork`는 "Claude Cowork의 오픈소스 대안"으로, **사람과 에이전트가 함께 쓰는 프로젝트 워크스페이스**다. 핵심은 멀티에이전트 협업 + 공유 컨텍스트 + 권한.

이 오픈소스가 상용 카테고리(Claude Cowork, 07-21 Nautis·Campus)를 그대로 겨눈다. 즉 "AI 워크스페이스"는 *멀티에이전트 오케스트레이션 + 공유 메모리 + 도구 커넥터 + 권한(authz)* 의 조립. openwork 코드를 보면 상용 워크스페이스가 내부적으로 무엇을 엮는지, 그리고 **오픈소스가 상용 대비 어디를 파고드는지**(자체호스팅·주권)가 보인다.

즉 워크스페이스 제품 하나가 성립하려면 *오케스트레이션 + 메모리 + MCP + authz + 격리* 가 모두 필요하다. 이번 달 트렌드가 사실상 이 워크스페이스의 부품들이었던 셈 — openwork를 보면 그 조립도가 한눈에 그려진다.

## 🟣 Tech → Business (기술에서 비즈니스로)

**"AI 인프라 리코닝" → 효율·오픈·런타임 보안이 새 차별점, 과잉·락인은 벌받는다**

The New Stack이 **"2026년 AI 인프라는 정산(reckoning)을 맞는다"** 고 경고한다 — 과잉 프로비저닝된 GPU와 부풀린 비용의 청구서. 그 답이 오늘 CNCF에 있다: **CoHDI(컴포저블·분리 인프라)** 로 유휴 GPU/메모리를 회수·재조합하고, **scale-to-zero**로 유휴를 없애며, **런타임 공급망 검증(NRI)** 으로 보안을 API가 아닌 실행 층에서 건다. 여기에 **openwork** 같은 오픈소스가 상용 워크스페이스의 마진을 압박한다.

방향: AI 인프라 경쟁이 "더 많이 사자"에서 **"가진 걸 효율적으로·안전하게·오픈하게"** 로 이동한다. 과잉투자·락인은 리코닝에서 벌받고, **효율(원가)·오픈(주권)·런타임 보안** 이 구매 기준이 된다. 솔루션 벤더 시사점: 고객에게 **"우리는 GPU를 적게·공유해서 쓰고, 런타임까지 검증하며, 자체호스팅(오픈) 가능"** 을 증명하는 쪽이 리코닝의 승자.

## 🔬 Enterprise Deep Dive — 에이전트가 만드는 IaC + 검증 게이트 (Ansible/Terraform)

> 오늘의 1 Pick. 에이전트가 인프라 변경을 초안 작성하면 속도는 나지만, 잘못된 playbook 하나가 사고. **생성 다음의 검증 파이프라인**이 핵심.

### 왜 쓰나 (도입 근거)
- **해결 문제**: 반복적 인프라 변경(설치·설정·배포)을 에이전트가 초안 작성 → 사람은 검토에 집중. 단, LLM은 **없는 리소스·파괴적 변경**을 만들 수 있어 그대로 적용하면 위험.
- **대안 대비**: *사람이 전부 수기 IaC*(느림) ↔ *에이전트 생성 + 자동 검증/승인*(빠르고 안전).
- **도입 효과**: 배포 리드타임↓, 표준화(정책 강제), 검토 부담↓ — 솔루션 설치/온프렘 배포 실무에 직결.
- **비용/리스크**: 환각 리소스, 파괴적 변경, 상태 드리프트, 시크릿 노출.

### 어떻게 연동하나 (기술 통합)
- **스택 위치**: `에이전트(생성)` → `lint` → `dry-run` → `정책검사(OPA/Conftest)` → `사람 승인(PR)` → `GitOps(ArgoCD, 07-29) 적용`.
- **최소 통합(개념 예시)**:
```bash
# 에이전트가 생성한 IaC를 "적용 전"에 반드시 통과시키는 게이트
ansible-lint site.yml                       # 문법·베스트프랙티스
ansible-playbook site.yml --check --diff     # dry-run(실제 변경 없이 영향 확인)
conftest test site.yml                        # OPA 정책(금지 리소스/파괴 동작 차단)
# 통과분만 PR → 사람 승인 → ArgoCD가 선언형으로 적용
```
- **운영 고려**: **적용은 항상 사람 승인 후**(07-23 authz 패턴), 시크릿은 vault 참조(하드코딩 금지), 상태(state)는 원격 잠금, 변경은 GitOps로 감사가능하게.
- **함정(gotchas)**: ① dry-run 없이 apply(사고), ② 환각 리소스명, ③ terraform state 드리프트, ④ 로그·playbook에 시크릿 노출.

### 도입 판단 체크리스트
- [ ] 반복적 **인프라 변경/설치**가 잦은가?
- [ ] **dry-run/plan**(--check, terraform plan)이 가능한 환경인가?
- [ ] **정책검사(OPA/Conftest)** 를 걸 수 있는가?
- [ ] **승인 + GitOps** 파이프라인이 있는가?

→ 2개 이상 Yes면 *에이전트 생성 → lint·dry-run·정책 게이트 → 승인 → GitOps* 순으로. "생성"보다 **"검증 게이트"** 를 먼저 세우는 게 안전의 핵심.
