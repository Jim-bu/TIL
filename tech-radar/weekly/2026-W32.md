## 🧭 PM 업무 단계별 시사점

### 1) 계약·제안 (Pre-sales / Scoping)
- **원가·ROI를 제안에 명시**(08-07): "건당/월 원가 + 성과(절감 시간·처리량)". *OCR은 건당원가↔ROI가 또렷해 스토리가 쉽다.*
- **효율을 원가 강점으로**(08-03): 저사양 추론(airllm류)·scale-to-zero → "고객의 (모자란) 하드웨어에서도 싸게".
- **재사용 블록으로 제안 표준화**(08-04): 일회성 대신 표준 블록(문서추출·메모리·배포템플릿) → 견적 일관성·속도.
- **보안 요구 선반영**(08-05): 문서 입력은 프롬프트 인젝션 노출 → "행동 로그·이상탐지·감사"를 제안 항목으로.

### 2) 수행·협업 (개발자·디자이너 소통)
- 개발팀 공유: **문서 인제스트 파이프라인**(분류→OCR/텍스트→청킹→eval, 08-04), **에이전트 관측·위협탐지**(OTel+uber/ADR, 08-05), **비용 라벨링**(team/customer, 08-07).
- **재사용 자산화**(08-04): 팀 공용 메모리 허브·표준 스킬로 반복 작업 제거.

### 3) 검수·테스트 (QA / 프로젝트 종료)
- **문서 추출 품질을 eval로**(08-04+07-29): 스캔·표·다단 케이스로 골든셋 구성 → 점수 기반 검수.
- **보안 검수**(08-05): 프롬프트 인젝션 **레드팀** + 이상행동 대응 플레이북.

### 4) 배포·설치 (Docker 이미지 / 온프렘)
- **효율 배포**(08-03): KEDA 이벤트 스케일 + **scale-to-zero**로 고객 GPU 유휴 비용 제거.
- **저사양 배포**(08-03): airllm류로 큰 모델을 작은 GPU에 → 고객 하드웨어 제약 대응.
- **문서 파이프라인 컨테이너화**(08-04): PDF 분류·OCR·청킹을 재현가능한 이미지로.
- **비용 라벨링**(08-07): 배포 워크로드에 `team/customer/feature` 라벨 → OpenCost showback/차지백.

### 5) 고객 인프라·서비스 안내 (Advisory)
- **원가·성과 대시보드 제공**(08-07): 건당 원가·ROI를 고객에게 투명하게.
- **관측·보안 설명**(08-05): "고객 문서를 넣어도 유출·오작동을 이상탐지로 막고, 전 행동을 감사".
- **효율 안내**(08-03): GPU 공유·scale-to-zero로 유휴 없앰.
