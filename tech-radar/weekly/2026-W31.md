## 🧭 PM 업무 단계별 시사점

### 1) 계약·제안 (Pre-sales / Scoping)
- **"어떤 모델"은 협상력 상실**(상품화) → 제안 차별화를 **신뢰성·운영·비용 투명성**으로 이동.
- **Eval을 계약 산출물로**: "정확도/일관성 수치 + 회귀 게이트 통과"를 SLA·검수 기준으로 제안서에 명시.
- **비용 투명성 제안**: LLM 사용 **비용 대시보드 제공**을 항목화(고객의 "AI 비용 얼마?" 대응).
- **리코닝 대비**: 고객이 GPU 과잉투자·락인을 경계 → "GPU 적게·공유·자체호스팅"을 **원가·주권 강점**으로.

### 2) 수행·협업 (개발자·디자이너 소통)
- 개발팀 공유: **eval 파이프라인**(골든셋+CI 게이트), **OTel `gen_ai` 계측**(관측·비용), **규칙+LLM 하이브리드**(신뢰).
- AIOps 실무 규칙: K8s 트러블슈팅·Ansible 생성 에이전트는 **read-only + 검증 게이트 우선**(파괴적 액션은 승인).
- **기술부채 인지**: 에이전트 코드도 유지·회귀 비용이 든다 → 스프린트에 "유지·eval" 작업을 명시적으로 반영.

### 3) 검수·테스트 (QA / 프로젝트 종료) — ★ 이번 주 핵심
- **검수 기준 = eval 골든셋으로 문서화** → 주관적 검수를 **점수 기반 합격/불합격**으로 전환.
- **납품 산출물**: eval 리포트 + 회귀 게이트 통과 이력 + **GitOps 배포 이력**(ArgoCD).
- **배포 전 시뮬/스트레스 테스트** + 온라인 평가(OTel 실트래픽 샘플).

### 4) 배포·설치 (Docker 이미지 / 온프렘)
- **에이전트 생성 IaC**(설치·설정 스크립트)는 반드시 *lint → dry-run(--check/plan) → 정책검사(OPA/Conftest) → 승인 → GitOps* 게이트 통과 후 적용.
- **런타임 공급망 검증(NRI)**: 이미지·모델을 API가 아닌 **실행 층에서** 무결성 검증(07-22 서명·스캔의 런타임 버전).
- **효율 배포**: GPU **공유(HAMi)·scale-to-zero**로 고객 원가 절감 → 설치 리소스 명세에 반영.

### 5) 고객 인프라·서비스 안내 (Advisory)
- 설명 항목: OTel 관측(비용·성능), eval(품질 보증), GitOps(재현·감사), 효율(GPU 공유·scale-to-zero), 런타임 보안(NRI), 자체호스팅(주권).
- **서비스 안내에 "AI 비용·성과 대시보드 + 품질 리포트" 포함** → 신뢰·리텐션 상승.
- 리코닝 시대엔 **오픈/자체호스팅 옵션**을 강조해 락인 경계 고객에 어필.
